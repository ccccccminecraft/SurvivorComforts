# 機能の洗い出しと実装機能リスト

前提：B42.21以降 / マルチプレイ / サーバーのMODリストに登録（基本は `client/` のみ。必要な機能だけ `server/` を同梱） / Workshopで限定公開 / 1つのMODにまとめ、機能ごとにMod OptionsでON/OFF

方針：ワールド（セーブデータ）に書き込まない。後からサーバーのMODリストから外しても、ワールドに影響が出ないようにする
- 設定は各自のPCの `ModOptions.ini` に保存されるだけ
- 例外：F06（共有ウィッシュリスト）とF09（未ログインユーザー表示）は、サーバーにデータを保存しないと実現できない。MODを外しても、使われないデータが残るだけで害が出ないように作る
- 新しいアイテム・レシピ・ゲームのルールは追加しない（ゲームバランスを変えない）

## 2. 調査結果

1章の機能ごとに、次の観点で調べて書く（主にClaudeが記入する）。

- 既存MOD：同じことができるMODの名前とWorkshop ID
- B42.21のMPで動くか：Workshopページの対応バージョンと、最近のコメントで確かめる
- クライアントだけで実現できるか：サーバーとのデータ同期やサーバー側の処理が要らないか
  - MODはサーバーのMODリストに登録するので、`server/` フォルダのLuaも**同じMODに同梱すればサーバーで動く**（追加の導入作業は不要）。
  - ただし、サーバー側の処理はサーバーの負荷や安定性に影響するので、必要最小限にする。
- 難しさ：既存UIの拡張で済むか、新しいUIが必要か、Luaで触れない部分か
- 判定：次のどれか
  - 既存MOD：既存のMODをサーバーに入れてもらえば済む
  - 自作：既存のMODがない、動かない、または一部だけ欲しい
  - 見送り：実現できない、または難しさに対して効果が小さい

※「B42.21のMPで動くか」は、Workshopページへのアクセスが制限されて確認できなかったものが多い。「未確認」としたものは、実際に試すか、ページとコメントを見て確かめる。

### F01: 日本語対応
- 既存MOD：ほかの人が作った個別のMODがある（ソースコードを共有してもらう予定）
- B42.21のMPで動くか：未確認（作者か、実際に使っている人に確認する）
- クライアントだけで実現できるか：できる見込み（入力処理はクライアント側だけの話）
- 難しさ：低（同梱するだけ）。ただし、入力処理がJava側に関わる場合は、Luaだけで実現できているかを確認する
- 判定：**同梱**
- 注意：Workshopで再配布するので、作者から**同梱と再配布の許可**をはっきりもらっておく。説明文に作者のクレジットを載せる

### F02: インベントリ検索
- 既存MOD：ほかの人が作った個別のMODがある（ソースコードを共有してもらう予定）。参考：Better Containers（3586216562）にも検索機能がある
- B42.21のMPで動くか：未確認
- クライアントだけで実現できるか：できる（インベントリ画面の表示だけの話）
- 難しさ：低（同梱するだけ）
- 判定：**同梱**
- 注意：F01と同じく、作者から許可をもらい、クレジットを載せる

### F03: レシピの材料のレシピを辿る
- 既存MOD：
  - Neat Crafting [B42]（3502080466）：クラフト画面を作り直したMOD。「クラフトの連鎖を辿れる」とされている。NeatUI Frameworkが必要
  - Context Menu Crafting [B42]（3425516353）：アイテムを右クリックすると、それを**材料として使う**レシピを表示する（逆方向）
- B42.21のMPで動くか：未確認
- クライアントだけで実現できるか：できる（レシピの情報はクライアントも持っている）
- 難しさ：中（2026-10-30 の整理で、絞り込みは本体と F12 の処理を使えると分かったため、中〜高から下げた）。B42のクラフト画面は構造が複雑で、ゲームの更新で変わりやすい
- 判定：**自作（範囲を絞る）**
- Neat Craftingを使わない理由：
  - Neat CraftingとNeatUI Frameworkの2つに依存し、更新が止まったり壊れたりしても自分たちでは直せない
  - セーブデータに何か書き込むか確認できておらず、外したときの影響が読めない
  - 多機能すぎて、ゲームバランスへの影響が心配
- F12・F06・本体との重なり（2026-10-30 整理）
  - 「材料を作れるレシピに絞り込む」こと自体は、本体にすでにある。制作の画面で材料のアイコンを Shift+クリックすると、その材料を完成品の名前で検索した絞り込みになる（`ISWidgetInput:onMouseDown`）。ただし画面のどこにも説明がなく、知らないと使えない
  - F12 の「レシピを見る」（`Recipes.lua` の `SurvivorComforts.showRecipes`）は、この本体の絞り込みを呼んでいるだけ。作るレシピがあるかの判定（`SurvivorComforts.hasRecipe`）も `Recipes.lua` にある。F03 はこの2つをそのまま使い、絞り込みの処理を新しく作らない
  - 制作・建築の画面の右クリック（材料・完成品のアイコン、材料の「使えるアイテムの一覧」、レシピ一覧）は、F06 がウィッシュリストのために拾っている。F03 も同じ場所を右クリックするので、別々に拾うと1回の右クリックでメニューが2つ開いてしまう
  - したがって F03 で新しく作るのは「材料の右クリックに『レシピを見る』を足すこと」と「たどった後に戻ること」の2つだけ
- 範囲：
  - 制作・建築の画面で、材料のアイコンと、材料の「使えるアイテムの一覧」の行を右クリックすると「レシピを見る」が出る（今アイコンに表示されているアイテムが対象。F06 と同じ）
    - 選ぶと、本体の Shift+クリックと同じ絞り込みで、その材料を作れるレシピを出す（`SurvivorComforts.showRecipes`）。建築の画面からは、制作の画面を開いて絞り込む
    - 作るレシピがない材料では、F06 の一覧と同じく赤い選べない表示にする（`SurvivorComforts.hasRecipe`）
    - 完成品のアイコンとレシピ一覧の行には出さない（今見ているレシピそのものなので）
  - 戻る：「レシピを見る」でたどる前の状態（検索の文字と種類、選んでいたレシピ）を覚えておき、制作の画面の検索欄の横に出す「戻る」ボタンで1つずつ前に戻る
    - 覚えるのは10段まで。制作の画面を閉じると忘れる
    - F12 やウィッシュリストの一覧から「レシピを見る」を選んだときも、制作の画面が開いていれば、その前の状態を覚える
  - 右クリックの共通化：制作・建築の画面の右クリックを拾う処理を F06 から共通のファイル（`client/SurvivorComforts/CraftMenu.lua`）に移す。F06 と F03 はそこに「このアイテムのときに出す項目」を登録し、1回の右クリックで1つのメニューにまとめて出す（画面左のボタンの `Sidebar.lua` と同じ考え方）。それぞれの機能が OFF のときは、その項目だけ出ない
  - オプションで ON/OFF できる（初期値ON）
  - 本体のクラフト画面をそのまま使い、作り替えない。本体の左クリック・Shift+クリックの動作は変えない
  - 新しくクラフトできるものは増やさない。本体のレシピ情報を見やすくするだけ
  - セーブデータには何も書き込まない

### F04: 本を読み終えるまでの残り時間
- 既存MOD：見つからなかった（読む速さを変えるMODはある：Faster Reading、True Readingなど）
- B42.21のMPで動くか：―
- クライアントだけで実現できるか：できる。読書のアクション（`ISReadABook`）から、残りのページ数と1ページあたりの時間を取得して計算する
- 難しさ：低
- 判定：**自作**
- 案：読書中の進捗バーかツールチップに「残り約○時間（ゲーム内）／約○分（現実）」を表示する。現実の時間は、サーバーの1日の長さの設定から換算する

### F05: ショートカットキーでマップに印をつける
- 既存MOD：Quick'n'Auto Mark（3579410548）：建物に自動で印をつける。ただし、マルチプレイでの動作は未確認
- B42.21のMPで動くか：未確認
- クライアントだけで実現できるか：できる。ゲーム本体のマップの記号は、マルチプレイではゲームが自動でサーバーと同期する（`ISWorldMapSymbols.lua` の `sendModifySymbol` など）。本体と同じ方法で記号を追加すればよい
- 難しさ：低〜中
- 判定：**一旦見送り**（4章「実装しない機能」へ）。再開するときは、既存MODを試してから自作を判断する（Quick'n'Auto Markは自動で印をつけるので、「1ボタンで手動で印をつける」という希望とは少し違う）
- 案：キーを押すと、プレイヤーが今いる建物の位置に、決めた記号を追加する。ペンなど書くものを持っていなければ追加しない（本体の `canWrite()` と同じ判定）

### F06: ウィッシュリスト
- 既存MOD：見つからなかった
- B42.21のMPで動くか：―
- クライアントだけで実現できるか：
  - 個人用：できる（自分のPCに保存するだけ）
  - プレイヤー全体で共有：**サーバー側のLuaが必要**。全体で共有するデータ（Global ModData）の通信を確認したところ、サーバーは受け取るとLuaのイベント（`OnReceiveGlobalModData`）を発生させるだけで、保存や配信は自動では行わなかった。サーバー側で保存と配信を行う処理を `server/` に同梱する
- 難しさ：個人用は低〜中、共有は中
- 判定：**自作**（まず個人用、次に共有）
- 案：アイテムを右クリックして「ウィッシュリストに追加」。そのアイテムを拾える場所で目印を出す、インベントリ画面で強調表示する
- 個人用の範囲（実装済み）：
  - インベントリ・周りの容器のアイテムを右クリックして追加・外す。リストにある種類は一覧の行を色付けする
  - 一覧のウィンドウで確認・外す。開くのは画面左のアイコンのボタン（オプションで表示・非表示）かキー。アイテムの右クリックには「開く」を出さない
  - リストは自分のPCの `Zomboid\Lua\SurvivorComforts_Wishlist.txt` にだけ保存する（ワールドには書き込まない）
- 制作・建築の画面からも追加できる
  - 材料・完成品のアイコンを右クリック：アイコンに今表示されているアイテムだけを追加・外す（代わりに使える候補すべては出さない）
  - 材料をクリックすると開く「使えるアイテムの一覧」の行を右クリック：その行のアイテムを追加・外す
  - レシピ一覧（リスト表示とアイコン表示）の行を右クリック：そのレシピの完成品を追加・外す。建築のレシピは完成品がアイテムではないので、材料の右クリックを使う
  - 本体の左クリック・Shift+クリック（絞り込み）の動作は変えない
- 画面左のアイコンのボタンは、スキルウィンドウ（F08）と共通の仕組み（`Sidebar.lua`）で並べる。非表示のボタンは隙間を空けずに詰める
- 一覧のウィンドウで行を右クリックすると、次の2つが出る
  - 「ウィッシュリストから外す」
  - 「レシピを見る」：本体の制作の画面を開き、そのアイテムを作れるレシピに絞り込む。本体で材料を Shift+クリックしたときと同じ絞り込み（完成品の名前で検索、知らないレシピも表示）を使う。建築の画面は対象外
- 共有版（みんなのリスト）の範囲：
  - 考え方：編集するのは自分のリストだけ。自分のリストのアイテムを「共有」すると、みんなのリストに出る。みんなのリストは、誰かが共有しているアイテムを集めて見るための閲覧用
  - 操作の流れ
    1. ウィッシュリストに追加：自分のリストに入る（共有はしない）
    2. 共有する：自分のリストに残したまま、みんなのリストにも出る
    3. 共有を解除：自分のリストには残り、みんなのリストからは自分の分だけ外れる
    4. ウィッシュリストから削除：自分のリストから消える。共有していたら、共有も一緒に解除する
  - 同じアイテムを何人でも共有できる。サーバーはアイテムごとに「共有している人」の一覧を持ち、解除はその人の名前だけを外す。全員が外れたときに、みんなのリストから消える（ほかの人の共有を巻き込んで消さない）
  - 共有を解除できるのは、共有した本人だけ。サーバーは、コマンドを送ってきたプレイヤーの名前でだけ外す。例外として、管理者は「みんなのリストから外す」で、そのアイテムの共有を全員分まとめて外せる（やめた人の共有を片付けるため）
  - 右クリックのメニュー（インベントリ・周りの容器、制作・建築の画面、一覧のウィンドウの「自分」タブで共通）：「ウィッシュリスト」の下に、アイテムの状態に合わせて出す
    - 自分のリストにない：「ウィッシュリストに追加」
    - 自分のリストにあり、共有していない：「共有する」「ウィッシュリストから削除」
    - 自分のリストにあり、共有している：「共有を解除」「ウィッシュリストから削除」
    - 種類の違うアイテムをまとめて選んだときは、アイテム名ごとにその項目を並べる
  - 自分が共有しているアイテムは、自分のリストのファイルに無くても、自分のリストに出す（自分のリストはサーバーやセーブをまたいで同じものを使うので、別のサーバーにいる間に削除すると、前のサーバーの共有だけが残るため。そのサーバーに戻れば、削除や共有の解除ができる）
  - 色付け：自分のリストはオレンジ、みんなのリスト（ほかの人の共有を含む）は水色。両方に入っているものは左端の印が2本になる
  - 一覧のウィンドウ：本体のタブ（`ISTabPanel`、キャラクター情報と同じ見た目）で「自分」「みんな」を切り替える
    - 「自分」タブ：自分が共有しているアイテムには水色の印を付ける。右クリックは上のメニューと「レシピを見る」
    - 「みんな」タブ：閲覧用。名前の後ろに共有している人を出す（2人までは「（Aさん、Bさん）」のように名前、3人以上は「（3名以上）」）。右クリックは「レシピを見る」と、自分のリストにないときは「自分のリストに追加」（共有はしない）。管理者には「みんなのリストから外す」も出す
    - 下のボタン「選んだものを外す」は「自分」タブでだけ使え、「ウィッシュリストから削除」と同じ動きにする
  - オプション「みんなのリストを使う」（初期値ON）。OFFにすると、共有の項目・水色・「みんな」タブが消え、自分のリストだけの表示・メニューに戻る（サーバーにある自分の共有はそのまま残る）
  - 保存と配信はサーバー側のLua（`server/SurvivorComforts/F06_SharedWishlist.lua`）で行う
    - ワールドの Global ModData（`SurvivorComforts_SharedWishlist`）に、アイテムごとの共有している人（とその順番）を保存する。方針の例外で、MODを外してもこのデータが残るだけで害はない
    - 前の形（アイテムごとに追加した人1人）のデータは、読み込んだときに「追加した人が共有している」形に置き換える
    - クライアントからは `sendClientCommand` で「一覧をください」「共有する」「共有を解除」「（管理者）外す」を送る。サーバーは一覧が変わるたびに、全員に `sendServerCommand` で一覧を送る
    - ログインしたときに一覧を受け取る
    - サーバー側で確かめること：存在するアイテムか、リストが多すぎないか（300種類まで）、管理者の操作は送ってきた人が管理者か
    - シングルプレイ：クライアントからの `sendClientCommand` はゲームが内部でサーバー側のLuaに渡すが、サーバーからの `sendServerCommand` は何もしない（ゲーム本体で確認）。そのため、シングルプレイのときだけ、サーバー側のLuaから `triggerEvent("OnServerCommand", ...)` で直接クライアント側に一覧を渡す

### F09: ログインしていないプレイヤーの表示
- 既存MOD：見つからなかった（Offline Survivorは、ログアウトしたキャラクターを世界に残すMODで、目的が違う）
- B42.21のMPで動くか：―
- クライアントだけで実現できるか：**できない。サーバー側のLuaが必要**。クライアントは、今ログインしているプレイヤーしか知らない。サーバー側で、ログインしているプレイヤーと最終ログイン日時を定期的に記録して保存し、クライアントの求めに応じて返す処理を `server/` に同梱する
- 難しさ：中
- 判定：**自作**（サーバー側の処理あり）
- 案：プレイヤー一覧のウィンドウ。ログイン中と未ログインを分け、未ログインの人には「最終ログイン：○日前」を表示する。7日以上ログインしていない人は表示しない
- 注意：最終ログイン日時がわかるのは、このMODを入れた後にログインした人だけ

#### 遊び方ごとの動き
| | シングル | セルフホストのマルチ | 専用サーバーのマルチ |
| --- | --- | --- | --- |
| サーバー側の処理が動く場所 | ― | ホストのPCで、ゲームとは別に起動するサーバー | サーバーのマシン |
| サーバーが動いている間 | ― | ホストが遊んでいる間だけ | いつも |
| 記録の保存先 | ― | ホストのPCのセーブデータ | サーバーのセーブデータ |
| 動き | **機能を出さない**（ボタンも出さず、何も記録しない） | 専用サーバーと同じ | 基本の作り |

- セルフホスト（メニューの「ホスト」）では、ホストのPCの中でゲームとは別にサーバーが起動し、ホスト自身もそこに接続する参加者の1人になる。そのため専用サーバーと同じ処理がそのまま動く。ホストがいない間はサーバーが止まっているが、その間は誰も入れないので記録に穴はできない

#### 作り
- サーバー側（`server/SurvivorComforts/F09_PlayerList.lua`）
  - ログイン・ログアウトを知らせるイベントは無いので、ゲーム内の1分ごと（`EveryOneMinute`）に、ログイン中のプレイヤー全員の「最後に見かけた時刻」を現実の時刻で記録する（書き込みは30秒に1回まで）。ログアウトした時刻の代わりに、最後に記録した時刻を使う
  - 「誰もいないとゲームを止める」設定のサーバーでも、止まるのは全員がいなくなった後なので、最後の時刻は記録できている
  - サーバーのセーブデータ（ModData）に、ユーザー名ごとに時刻を1つだけ持つ。30日以上来ていない人のデータは消す
  - 参加者から頼まれたら、記録している全員の最後の時刻と、サーバーの現在時刻を返す。「何分前」の計算はサーバーの時計で揃えるので、各自のPCの時計がずれていても狂わない
- 参加者側（`client/SurvivorComforts/F09_PlayerList.lua`）
  - 画面左に人のアイコンのボタンを足し、プレイヤー一覧のウィンドウを開く。ボタンの表示・非表示と、開くキー（初期値なし）をオプションで選べる
  - 「オンライン」と「オフライン」に分けて表示する
  - オンラインの人は、本体の「ユーザー一覧」と同じ仕組み（`scoreboardUpdate()` → `OnScoreboardUpdate`）で、今の接続者をサーバーから直接受け取る。誰かが入ったり出たりすると届く `OnMiniScoreboardUpdate` で、開いている間もすぐに更新する
  - オフラインの人は、サーバーの記録のうち、今オンラインではない人。最後に見かけたのが新しい順に並べ、7日以上来ていない人は表示しない
  - 最終ログインは、1時間未満は「○分前」、1日未満は「○時間前」、それ以上は「○日前」と表示する（切り捨て。1分未満も「1分前」）
  - 「○分前」は、保存してある最後の時刻（日時）と、サーバーの今の時刻の差で毎回計算する。経過時間を足し続ける作りではないので、ずれが積み重ならない
  - ウィンドウを開いたときと、開いている間は1分ごとに、サーバーに聞き直す
- 名前はキャラクター名ではなくユーザー名を使う（キャラクター名は、死んで作り直すと変わるため）
- セルフホストでホストのゲームが落ちると、最後の保存より後の記録は失われる。表示される最終ログインが少し古くなるだけで、害はない

### F10: PvPの切り替えボタンを非表示にする
- 既存MOD：見つからなかった
- B42.21のMPで動くか：―
- 本体の仕組み（`ISEquippedItem.lua` で確認）：
  - 画面左のドクロのボタン（セーフティ）は、マルチプレイで、サーバー設定 `SafetySystem` がONのときだけ表示される
  - 切り替えはボタンのほか、キー（初期値 `G`、`KeybindId.TOGGLE_SAFETY`）でもできる。どちらも `ISEquippedItem:toggleSafety()` を通る
  - サーバー設定 `PVP=false` にすると、セーフティの状態に関係なく、プレイヤー同士でダメージが入らない
- **サーバーの設定だけで済む可能性が高い**：
  - PvPを一切しないなら、サーバー設定（`servertest.ini` など）で `PVP=false` にする。事故の心配自体がなくなる
  - さらに `SafetySystem=false` にすると、ボタンも出なくなる（ボタンの表示はこの設定だけで決まる）
- MODで作る場合（PvPを時々使いたいなど、サーバー設定を変えたくないとき）：
  - クライアントだけでできる。ボタンを隠し、`toggleSafety()` を何もしないように差し替えれば、キーでも切り替わらなくなる
  - 注意：セーフティがOFF（PvP状態）のときに隠すと、元に戻せなくなる。セーフティがONのときだけ隠す、などの対策が要る
  - ボタンの下にある本体のボタン（ユーザー一覧、管理者など）が詰まらず隙間が残るので、位置を詰める処理も要る
- 難しさ：サーバー設定なら不要。MODなら低
- 判定：**自作**（サーバー設定は変えず、クライアント側で隠す）
- 範囲：
  - 機能の「有効にする」がONの間（初期値ON）、次のようにする
  - 画面左のドクロのボタンを隠す。下にある本体のボタン（ユーザー一覧、管理者など）は、隙間ができないように上に詰める
  - 無条件でPvPをオフ（セーフティを有効）にする。オフでないときは、本体と同じ方法（`Safety:toggleSafety()`、マルチではサーバーに依頼）でオフに戻す。サーバー設定の切り替え時間（`SafetyToggleTimer`）や、攻撃直後の待ち時間があるときは、終わってから戻す
  - ボタン・`G` キーでの切り替えを無効にする（`ISEquippedItem:toggleSafety()` と、キーの処理 `ISEquippedItem.onKeyPressed` を差し替える）。シングルプレイの画面分割で `G` キーが切り替える協力プレイのPvPも、オフにして無効にする
  - 「有効にする」をOFFにすると、ボタンと位置が元に戻り、切り替えもできるようになる
  - セーブデータには何も書き込まない（セーフティの状態は本体の機能で切り替えるだけ）

### F11: インベントリのアイテムにロック機能を付ける
- 既存MOD：ロック専用のものは見つからなかった。LootSense（B42）はお気に入りやタグ付けを追加するが、一括移動の除外は本体の機能を使っている
- B42.21のMPで動くか：―
- 本体の仕組み（`ISInventoryPane.lua`、`ISInventoryPaneContextMenu.lua` で確認）：
  - **本体に「お気に入り」がある**。自分のインベントリのアイテムを右クリック →「その他」→「お気に入り」。一覧に星が付く
  - お気に入りのアイテムは、次の操作で移動されない
    - 「すべて移す」（`ISInventoryPane:transferAll`）
    - 「同じ種類を移す」（`TransferSameType`）
    - 自分のインベントリの外（周りの容器や床）へのドラッグ
    - 手に持った物・背負った物を落とすキー
  - お気に入りの印はアイテム自体に保存される（本体の機能なので、MODを外しても影響はない）
- **本体の「お気に入り」で希望はほぼ満たせる**。困っている場面（水などを一括でしまってしまう）は、水をお気に入りにすれば起きない
- 足りない点（MODで補うなら）：
  - 「お気に入り」が右クリックの「その他」の中にあり、見つけにくい・操作が多い。右クリックの一番上の階層に出す、またはキー1つで切り替える、なら低い難しさで作れる
- 難しさ：本体の機能を使うなら不要。補う場合は低
- 判定：**見送り**（本体の「お気に入り」を使う。4章「実装しない機能」へ）
