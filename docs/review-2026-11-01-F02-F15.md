# F02・F15 の点検（2026-11-01）

同梱した2つの機能、[F02 インベントリ検索](features/F02_inventory-search.md) と [F15 ほかの人のスキルを見る](features/F15_member-skills.md) のコードを、[全体の点検（2026-10-30）](review-2026-10-30.md) と同じ6つの観点で見直した結果。この時点ではまだ何も直していない。直したら、各項目の「状況」を更新する。

対象のファイル

- F02：`client/SurvivorComforts/F02_InventorySearch.lua`、共通の検索 `client/SurvivorComforts/Search.lua`（ひらがな・カタカナの処理と、1文字ずつ見る語の区切り方を足した部分）
- F15：`client/SurvivorComforts/F15_MemberSkills.lua`、`server/SurvivorComforts/F15_MemberSkills.lua`、`shared/SurvivorComforts/Skills.lua`、F09 の一覧から開く部分（`F09_PlayerList.lua` の `onClickRow`）、共通のウィンドウに足した `windows.open`（`Window.lua`）

観点

1. 共通化すべきところ
2. 性能が悪い・もっと良いやり方がありそうなところ
3. グリッチ（不正や想定外の使い方）になりうるところ
4. 連打したときに負荷が上がるところ
5. ほかの MOD と競合したり、無効にしたりするおそれのあるところ
6. そのほか、配る前に確かめたいこと

重要度：**高**（早めに直したい）／**中**（直すと良い）／**低**（余裕があれば）

状況：⬜ 未着手 ／ 🔧 対応中 ／ ✅ 対応済 ／ ⏸️ 見送り（理由を書く）

ID は、全体の点検（R）と分けるため、S で始める（S＋観点の番号＋連番）。

## 機械的に確かめて問題がなかったこと

- 構文チェックと自動の点検（`tools\check.ps1`）：エラーも警告もない。翻訳キーは日本語と英語でそろっていて、コードで使っているキーはすべてある。ゲームの Lua（Kahlua）にない関数は使っていない
- 意図しないグローバル変数：作っていない。新しく作ったクラスの名前（`SurvivorComforts_MemberSkillsList`・`SurvivorComforts_MemberSkillsWindow`）と、F09 から呼ぶ関数（`SurvivorComforts.showMemberSkills`）は、`SurvivorComforts` で始まる。元のコードのグローバル変数（`InventorySearch`・`SkillViewer`・`SkillViewerWindow`）は残っていない
- ゲーム本体の部品に足した項目の名前：すべて `survivorComforts` で始まる（`survivorComfortsSearchButton` など）。元の MOD（`invSearch...`）と名前がぶつからない
- 通信の名前：`SurvivorComforts` の中の `skillsRequest`・`skills`。ウィンドウの位置を覚えるキー：`survivorcomforts.memberskills`
- 本体の関数への割り込み：すべて、元の関数を呼んでから足している。置き換えて元を呼ばないものはない
- 新しい検索の処理（ひらがなとカタカナ、全角の空白での区切り、日本語の部分一致、英語名、内部名の単語、英字の判定、空の検索）は、ゲームの Lua で単体のテストを通した（2026-11-01）
- 「すべて取る」「すべて移す」への入り口：ボタン、右クリックのメニュー、新しい操作の部品（`LootWindow/Handlers/TakeAll.lua` など）は、どれも `ISInventoryPage.lootAll`／`transferAll` → `ISInventoryPane` の同じ関数を通るので、検索の絞り込みが漏れなく効く
- ワールドへの書き込み：どちらもしない

## 3. グリッチ（不正や想定外の使い方）になりうるところ

不正に使える処理は見つからなかった。F02 は画面の表示と、本体と同じ移動の操作だけ（実際の移動はサーバーが確かめる）。F15 のスキルはサーバーで読むので、ごまかせない。次は、仕様として知っておくべきこと。

| ID | 重要度 | 状況 | 内容 |
| --- | --- | --- | --- |
| S3-1 | 低 | ⬜ | F15：だれでも、オンラインのほかの人のスキルを見られる（仕様。身内のサーバー向けに、管理者だけに絞っていない）。説明文には書いてある |
| S3-2 | 要確認 | ⬜ | F15：改造したクライアントなら、F09 の一覧に出ていないユーザー名でもサーバーに聞ける。答えに中身があるかどうかで、そのユーザーがオンラインかが分かる。「見えない状態」の管理者がいることが分かってしまう可能性がある（全体の点検の R3-3 と同じ話。R3-3 は保留中） |

## 4. 連打したときに負荷が上がるところ

| ID | 重要度 | 状況 | 内容 |
| --- | --- | --- | --- |
| S4-1 | 中 | ⬜ | F15：F09 の一覧で人を続けてクリックすると、1秒に6回目からのサーバーへの問い合わせが、回数の制限で黙って捨てられる。最後にクリックした人の問い合わせが捨てられると、ウィンドウが「取得中…」のまま変わらない（もう一度クリックすれば直る）。サーバーの負荷は制限で守られている。画面側で「前の問い合わせから少し待ってから送る」（F09 の 5 秒のやり方と同じ）にすれば、最後のクリックが必ず届く |
| S4-2 | 低 | ⬜ | F02：検索欄に打つたびに一覧を作り直す（元のコードと同じ）。自分の PC の中だけの処理で、サーバーには何も送らない |

サーバーに届く F15 の問い合わせは、共通の安全弁（1人1秒5回まで）で守られている。元のコードの独自の制限（0.5秒に1回）は外した。
