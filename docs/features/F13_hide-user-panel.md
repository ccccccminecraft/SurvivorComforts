# F13 ユーザーパネルのボタンを隠す

- 状況：✅ 実装済
- コード：`client/SurvivorComforts/F13_HideUserPanel.lua`、共通の `Sidebar.lua`
- 一覧に戻る：[features.md](../features.md)

## 要望

最初の書き出しの後に出た要望

- 内容： 画面左のアイコンの列から、ユーザーパネル（派閥・セーフハウスなどを開くウィンドウ）のボタンを隠す。管理者には、設定に関係なく表示する
- 困っている場面・理由: 身内では派閥を一切使っておらず、アイコンの列が窮屈になっている
- 優先度: 中

## 調査結果

- 既存MOD：探していない（F10 と同じ仕組みで作れるため）
- B42.21のMPで動くか：―
- 本体の仕組み（`ISEquippedItem.lua` で確認）：
  - ボタンは `ISEquippedItem` の `clientBtn`（`internal = "USERPANEL"`）。マルチプレイのときだけ作られ、押すとユーザーパネル（`ISUserPanelUI`）が開く。中に「派閥」「セーフハウス」「チケット」「サーバーの設定を閲覧」などのボタンがある
  - その下に管理者のボタン（`adminBtn`、管理者の権限 `hasAdminTool()` があるときだけ表示）と、戦争のボタン（`warManagerBtn`、戦争中だけ表示）がある
  - F10 の PvP のボタンと同じく、ボタンを隠したら下のボタンを上に詰める必要がある
- クライアントだけで実現できるか：できる。ボタンを隠すだけで、派閥などの仕組みには触れない
- 難しさ：低
- 判定：**自作**

## 仕様

- 機能の「有効にする」がONの間（初期値ON）、画面左のユーザーパネルのボタンを隠し、下にあるボタン（管理者、戦争）を上に詰める
- 管理者には、設定に関係なくボタンを表示する
  - 管理者は、ほかのプレイヤーをキックできる人（最初からある役割では、管理者とモデレーター）。F06 と同じ判定で、`shared/SurvivorComforts/Admin.lua` の `SurvivorComforts.isAdmin` にまとめている（2026-10-31、点検の R1-1）
  - 本体の管理者のボタンの判定（`hasAdminTool()`）より狭い。GM とオブザーバーは、管理者のボタンは出るが、このボタンは隠れる
- 隠すのはボタンだけ。派閥・セーフハウスなどの機能は止めない（F10 と違い、放っておいても事故にならないため）
- 本体のボタンを隠して下を詰める処理は、F10 と共通にする（`Sidebar.lua`）。F10 と F13 の両方で隠しても、隙間ができない
- 「有効にする」をOFFにすると、ボタンと位置が元に戻る
- セーブデータには何も書き込まない

## 確認項目

準備：ボタンはマルチプレイでしか出ないので、テスト用のサーバーで確かめる（[dev-guide.md の「1台で複数人を試す」](../dev-guide.md#1台で複数人を試す)）。管理者の確認は、サーバーの画面で `setaccesslevel <ユーザー名> admin` を打ってから行う。

- [ ] オプション →「MOD」に「ユーザーパネルのボタンを隠す」が、「PvPの切り替えボタンを隠す」の下に表示される（初期値ON）
- [ ] 管理者でない人では、画面左のユーザーパネルのボタンが出ない。下のボタンが上に詰まり、隙間がない。この MOD のボタン（スキルなど）もその下に詰まる
- [ ] F10 もONのとき、PvP とユーザーパネルの両方のボタンが消え、隙間がない。どちらか一方だけOFFにしても、隙間なく並び直す
- [ ] 管理者には、ONでもユーザーパネルのボタンが出る。ゲーム中に管理者にすると、すぐに出る
- [ ] 「有効にする」をOFFにすると、ボタンが元の位置に戻り、押すとユーザーパネルが開く
- [ ] 派閥のチャットや、マップの派閥への共有など、ほかの場所の派閥の機能は今までどおり使える
- [ ] シングルプレイでエラーが出ない
