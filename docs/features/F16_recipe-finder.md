## 要望

- 内容：アイテム名で検索して、そのアイテムの作り方（製作・建築・料理・修理）と使い道（何の材料・道具になるか）を、ゲームの中のウィンドウで調べられるようにする。材料の作り方も順にたどれるようにする
- 困っている場面・理由：本体の製作の画面は「今作れるか」を見る画面で、「このアイテムは何に使えるか」「材料をどこから作るか」をまとめて調べにくい。ゲームの外の HTML のツールでは調べられるが、ゲームを離れる必要があり、バニラ（MOD なし）の決まった版のデータしか載らない

## 調査結果

- 既存MOD：Context Menu Crafting [B42]（3425516353）は、アイテムの右クリックで、それを材料に使うレシピを出す（F12 の調査を参照）。作り方・使い道・材料の展開をまとめて調べる画面は見つかっていない
- B42.21のMPで動くか：―
- クライアントだけで実現できるか：できる。レシピはどれもクライアントにあるスクリプトのデータから読める。サーバーとのやり取りも、セーブデータへの書き込みも要らない
- データの量（B42.21 のゲーム本体のスクリプトを数えた）：
  - 製作のレシピ（`craftRecipe`）約970、建築の項目（`entity`）約460、料理（`evolvedrecipe`）約440、修理（`fixing`）29
  - アイテムは約1万種類あるが、検索の対象はレシピに出てくるものだけ（数千）なので、最初に一度で索引を作っても引っかかりはほぼ出ない見込み（ゲームの中で測って確かめる）
- データの読み方（ゲームの Lua で使われているもの。B42.21 で確かめた）：
  - 製作：`ScriptManager.instance:getAllCraftRecipes()`
  - 建築：`ScriptManager.instance:getAllBuildableRecipes()`（製作の一覧には入っていない。2026-11-02 に、ゲームのクラスを見て確かめた）。建築のレシピも `CraftRecipe` で、建築かどうかは `isBuildableRecipe()`、建築の分類は `getBuildCategory()`、アイコンは `getIconTexture()`
  - 建築のレシピは、アイテムではなく設置物（壁・家具・設備など）を作るので、完成品のアイテムがない
  - 材料と完成品：共通の `SurvivorComforts.forEachRecipeItem`（`Recipes.lua`）で読める。材料1つごとに：
    - 消費しない（道具）か：`isKeep()`、`isTool()`
    - 数：`getIntAmount()`。数が決まっていないもの：`isVariableAmount()`
    - なれるアイテム：`getPossibleInputItems()`（「ハンマーならどれでも」のようなタグの指定も、アイテムの一覧に直して返す）
    - 液体・エネルギー：`getResourceType()` で分かる。液体は `getPossibleInputFluids()`
  - 必要なスキル・習得・明るさ・場所：`getRequiredSkillCount()` と `getRequiredSkill()`、`needToBeLearn()`、`canBeDoneInDark()`、`isAnySurfaceCraft()`、`isCanBeDoneFromFloor()`（本体の製作の画面 `ISWidgetTitleHeader.lua` などが使うもの）
  - 料理（スープ・サラダなど）：`getEvolvedRecipes()`（`ISInventoryPaneContextMenu.lua`）
  - 修理：`FixingManager.getFixes(item)`（`ISInventoryPaneContextMenu.lua`）。アイテムの実物を渡す形なので、全部の修理の一覧を読む方法は実装のときに調べる
- HTML 版との違い：
  - ゲームが読み込んだレシピをそのまま使うので、サーバーで入れている MOD のレシピも出る。ゲームを更新しても古くならない
  - 一覧のデータ（HTML 版は 3.4MB）を MOD に入れる必要がない。最初に開いたときに一度だけ索引を作る
- 使い回せるもの：
  - 共通の検索（`Search.lua`：ひらがなとカタカナを区別しない、空白で絞り込む）と、F14 の英語名の表
  - ウィンドウの共通部品（`Window.lua`）と画面左のボタン。一覧は F06・F09 と同じ `ISScrollingListBox` を元にする
  - F12 の「作れるアイテムの一覧」と、製作の画面を開いて絞り込む処理（`Recipes.lua`）
- 難しさ：中〜高。新しいウィンドウ（検索欄・結果の一覧・詳しい表示・材料の展開）が要る。料理と修理は、データの読み方を調べるところから
- 判定：**自作**（itsu07 さんの HTML のアプリを元に、Lua で作り直して Survivor Comforts に入れる）

### 画面

- 外枠は `Window.lua` で作る（F08・F09 と同じ。大きさを変えられ、位置と大きさを覚える）。最初の大きさは 1200×800（画面に収まらないときは、収まる大きさまで縮める）
- ウィンドウの名前は「アイテム検索」（アイテムから調べる画面のため。機能の名前は「レシピ検索」のまま）
- 開き方：画面左のボタンと、オプションで決めたキー（初期値はキーなし）
  - F12 の右クリック「レシピを見る」と、F06 のウィッシュリストから開けるようにするかは、段階 1 を使ってみてから決める
- 並び（HTML 版と同じ）：
  - 上：検索欄と、絞り込みの選択欄（すべて／製作／建築／料理／修理／作成不可。下の「絞り込み」）と、「作成可」のチェックボックス（下の「今作れるもの」）
  - 左：検索結果のアイテムの一覧（アイコンと名前）
  - 右：選んだアイテムの情報。いちばん上に「戻る」「進む」のボタンの列、その下に選んだアイテムの行（2026-11-02 に、ボタンを検索欄の左から移した）
- 右の情報は、文章の欄ではなく、1行ずつの一覧（`ISScrollingListBox` を元にする）で作る
  - いちばん上は選んだアイテムの行で、ほかの行より高くし、大きいアイコンと大きい文字の名前、その下に分類（インベントリと同じ表示）と内部名を出す
  - 行の種類：見出し（作り方・使い道）、レシピ（名前と「製作」「建築」の区別）、材料・道具、条件（スキル・習得・明るさ・場所）
  - アイテムの行をクリックすると、そのアイテムの情報に移る
- 「戻る」「進む」（ブラウザと同じ動き。2026-11-02 に「進む」を追加）：
  - 左の一覧で選ぶ、または右の名前を押してアイテムを移ると、前のアイテムが「戻る」の履歴に入り、「進む」の履歴は消える
  - 「戻る」で前のアイテムに戻ると、今のアイテムが「進む」の履歴に入る。「進む」で戻る前のアイテムに進む
  - 戻る先・進む先がないときは、そのボタンを押せない（灰色）
  - 履歴は 50 件まで。ウィンドウを閉じても残る（開き直したときも戻れる）
  - 段階 2 の「材料の展開」は、材料の下に字下げした行を足して作る（下の「材料の展開（段階 2）」）
- 作り方：レシピごとに
  - 材料（消費）と道具（消費しない）を分けて、数と一緒に出す
  - 「ハンマーならどれでも」のように、なれるアイテムが複数ある材料は「ハンマー など5種」と1行にまとめ、クリックで全部を開く
  - 液体の材料は、名前と量の文字だけで出す
  - 必要なスキル、習得が要るか、明るさが要るか、作る場所
- 使い道（逆引き）：材料として消費するレシピと、道具として使うレシピを分けて出す
- この画面から直接は作らない。右クリックのメニューから本体の製作・建築の画面を開いて作る（2026-11-02 に決定）：
  - 左の一覧と右のアイテムの行（選んだアイテム、材料・道具・完成品）：
    - 「製作する」：製作のレシピで作れるアイテムのとき。本体の製作の画面を、そのアイテムを作るレシピに絞り込んで開く（F12 の「レシピを見る」と同じ）
    - 建築のレシピはアイテムを作らない（設置物を作る）ので、アイテムには「建築する」は出さない
  - 右のレシピの行：「[製作]」なら「製作する」、「[建築]」なら「建築する」。本体の製作・建築の画面を、そのレシピを選んだ状態で開く（本体の読書の画面と同じ `ISEntityUI.OpenHandcraftWindow`・`OpenBuildWindow`）
  - どちらも、続けてウィッシュリストの行（F06。「ウィッシュリストに追加」など）を出す。レシピの行は、その完成品のアイテムについて出す。ウィッシュリストの行は、製作・建築の画面の右クリックと共通（`CraftMenu.lua` の `fillCraftMenu`）
- 出さないもの：HTML 版の「定義の原文」（ゲームの中ではスクリプトの原文が読めないため）と、ダーク表示の切り替え（ゲームの UI の色に合わせる）

### 表記

ゲームの日本語の画面と同じ言葉にする（2026-11-02 に決定）。ゲームの翻訳のキーをそのまま使えるところは使い、ほかの言語でもゲームと同じ言葉になるようにする。

| 意味 | 表記 | ゲームの翻訳のキー |
| --- | --- | --- |
| 製作（作業台・手で作る） | 製作 | `IGUI_CraftingWindow_Craft` |
| 建築（設置物を作る） | 建築 | `IGUI_CraftingWindow_Build` |
| 使ってなくなるもの | 材料 | `IGUI_CraftingWindow_Requires` |
| できるもの | 完成品 | `IGUI_CraftingWindow_Creates` |
| なくならないもの | 道具 | ゲームの日本語の翻訳がない（英語のまま「Tools」）ので、この MOD の翻訳 |

この MOD のほかの機能の説明（オプションの画面）も「製作」「材料」にそろえる。

### 建築物

- 建築のレシピ1つを、左の一覧の1行（建築物）として出す。名前はレシピの名前、アイコンはレシピのアイコン
- 選ぶと、右にその建築物の作り方（建築のレシピ。材料・道具・条件）を出す。分類の欄には「建築」と出す
- 絞り込みの「建築」で、建築物だけになる（下の「絞り込み」）
- 右クリック：「建築する」で、建築の画面をそのレシピを選んだ状態で開く。アイテムではないので、ウィッシュリストの行は出さない
- 検索は、レシピの名前で探す（F14 が ON なら英語名でも）

### 絞り込み

検索の結果を、次のどれかに絞る（2026-11-02 に「すべて／作れるもの／素材（作れない）／建築物」から変えた。2026-11-05 に「料理」「修理」を足した）。言葉は「表記」に合わせ、「製作」「建築」はゲームの翻訳をそのまま使う。

| 選択肢 | 出るもの |
| --- | --- |
| すべて | 全部（アイテムと建築物） |
| 製作 | 製作のレシピで作れるアイテム |
| 建築 | 建築物（建築のレシピ） |
| 料理 | 料理（材料を足す方式）の完成品になるアイテム |
| 修理 | 直し方があるアイテム |
| 作成不可 | 製作でも料理でも作れないアイテム（拾う・採る・解体するなどで手に入れるもの。直し方があるものも入る） |

- 「建築」は、ほかのどれとも重ならない（建築物はアイテムではない）。「作成不可」は「製作」「料理」と重ならない。「製作」と「料理」、「修理」とほかは重なることがある（2026-11-05 までは「製作・建築・作成不可を合わせるとすべて」だったが、料理と修理を足したので、それは崩れる）
- 「作成可」と組み合わせたとき、「料理」は「今作れる料理があるもの」、「修理」は「今直せるもの」（傷んだアイテムを持っていて、修理材・スキルもある）になる（2026-11-05 に、「料理」も料理だけで見るようにそろえた。それまでは、製作のレシピで作れるものも明るく出ていた）
- 今作れるかどうかは、この選択肢とは別の軸なので、選択肢には入れず、「作成可」のチェックボックスで絞る（下の「今作れるもの」）。選択肢とチェックボックスは組み合わせて使える（例：「建築」＋「作成可」で、今建てられる建築物だけ）

### 材料の展開（段階 2）

2026-11-02 に要件を決め始めた。材料の作り方を、別のアイテムに移らずに、その場で下へ順にたどれるようにする。

- 元になるもの：HTML 版の「原料を展開」。レシピごとのボタンで材料を木の形に並べ、▸ で1段ずつ開く。作り方・候補が複数あるときは選択欄で1つ選ぶ。作れないものは「素材（入手物）」、循環するものは「循環のため展開しません」と出る。道具は「道具も展開」にチェックを入れたときだけ。数は1回分で、合計は出さない
- この MOD での形（2026-11-02 に決定）：
  - 開ける場所：右側の、開いたレシピの中の材料の行。「作り方」のレシピも、「材料として使う」「道具として使う」（逆引き）のレシピも同じ
  - 材料の行で、そのアイテムが製作のレシピで作れるときは、行の頭に「[+]」を付ける。押すと、その下に1段字下げして、そのアイテムの作り方（レシピの行と、その中の材料・道具・完成品・条件の行）を足す。足した行の材料も、同じように開ける。今の見出しやレシピの「[+]」「[-]」と同じ動き
  - 作れないアイテム（拾う・採る・解体するなど）の材料には「[+]」を付けない
  - 循環する（開いた先に、上の段と同じアイテムが出る）ときは、そこから先は開けない
  - 深さの上限は 20 段。不具合で行が増え続けないための止めで、ふだん使う分には届かない数にする。上限の段の材料には「[+]」を付けない
  - 数は1回分のまま（合計は出さない）
  - 開いたかどうかは、今のレシピの開け閉めと同じく覚える（「戻る」「進む」で戻ったときも同じ形に戻る）
  - 選択欄は使わない（一覧の行の中に置けないため）。候補が複数ある材料は、今の「ハンマー など5種」の行を開くと候補が並ぶので、候補の1つ1つに「[+]」を付けて開けるようにする
  - 1つのアイテムに作り方が複数あるときは、開くと全部並べる（今の「作り方」と同じ。並びは下の「並び」）
  - 「作成可」にチェックが入っているときは、足した行の中でも、今作れないレシピを暗くする（段階 4 の右側と同じ）
- 道具（HTML 版と同じ）：
  - 道具（なくならないもの）の行は、初めは開けない（「[+]」を付けない）
  - 右側のいちばん上の列（「戻る」「進む」の右）に「道具も展開」のチェックボックスを置く。チェックを入れると、道具の行も材料と同じように開ける。初めはチェックなし。ウィンドウを閉じても覚える（「作成可」と同じ）
- 並び（2026-11-02 に決定。「作成可」のチェックに関係なく、いつもこの並びにする）：
  - 今アクセスできるインベントリ（自分の持ち物と、周りの容器・床。段階 4 と同じ範囲）を元に並べる
  - 候補が複数ある材料：その材料の数が足りている候補を先に、次に持っているが足りない候補、残りはゲームの並び（`getPossibleInputItems()` の順）。それぞれの中もゲームの並び
  - 「ハンマー など5種」の行の名前（1つ目）も、この並びの先頭にする（ただし、選んだアイテムが候補にあるときは、今と同じくそれを先にする）
  - 作り方が複数あるアイテム：今の持ち物で作れるレシピ（段階 4 と同じ判定）を先に、残りはゲームの並び。右側の「作り方」「材料として使う」「道具として使う」の並びも同じにする
  - 数は、液体以外のアイテムの個数で比べる（液体の材料は並べ替えない）
  - 持ち物が変わったら、段階 4 と同じ合図（`refreshBackpacks`）で数え直し、右側を描き直す。「作成可」のチェックがなくても、ウィンドウが見えている間は数え直す
- 気をつけること：
  - 重さ：作り方の並びのための判定は、段階 4 の判定（全レシピ）を、チェックがなくても使うことになる。重ければ、右側に出ているレシピだけを判定する形に変える（持っている数の数え方は、下の「負荷の見直し」で、容器の中を1回なめて全部数える形に決めた）

### 負荷の見直し（2026-11-02）

段階 2 では、「作成可」のチェックがなくても持ち物を見るようになるので、その前に、同じデータを何度も取っていないか、変わらないものを毎回計算していないかを見直した（コードを読んで。ゲームの中では測っていない）。

- 見つけたもの：

## 確認項目

段階 1：

- [ ] オプション →「MOD」の「レシピ」の見出しに「レシピ検索」が出て、その下に「左のアイコンにボタンを表示する」と開くキーがある
- [ ] 画面左に虫眼鏡のボタンが出る（スキル・ウィッシュリスト・プレイヤー一覧の下）。押すとウィンドウ「アイテム検索」が開き、もう一度押すと閉じる
- [ ] 初めて開いたときの大きさが 1200×800 ほど（位置と大きさを覚えたあとは、その大きさ）
- [ ] 初めて開いたときに、目立つ引っかかり（一瞬止まる）がない
- [ ] 検索欄に「板」「いた」「plank」と入れると、板が見つかる（英語名は F14 が ON のとき）。空白で区切ると、全部を含むものに絞り込む
- [ ] 検索欄が空のときは、選んだ絞り込みの中の全部が名前の順に出る（「すべて」なら全部）。文字を消すと全部に戻る
- [ ] 絞り込みが「すべて／製作／建築／料理／修理／作成不可」の6つで、それぞれで一覧が変わる。「製作」にはアイテムだけ、「建築」には建築物だけ、「作成不可」には製作でも料理でも作れないアイテムだけが出る
- [ ] 板を選ぶと、右のいちばん上に大きいアイコンと名前、その下に分類と内部名が出る。その下に「作り方」（開いた状態）と「材料として使う」（閉じた状態）が出る
- [ ] 作り方のレシピに、材料・道具・完成品と数、条件（スキル、習得、明かり、場所）が出る
- [ ] 「[+]」の行を押すと開き、「[-]」で閉じる。「ハンマー など○種」の行を押すと、なれるアイテムが並ぶ
- [ ] 緑の名前を押すと、そのアイテムに移る。「戻る」で前のアイテムに戻り、「進む」で戻る前のアイテムに進む。戻ったあとに別のアイテムに移ると、「進む」は押せなくなる
- [ ] 「戻る」「進む」のボタンが、右のいちばん上（選んだアイテムの行の上）にある。押せないときは灰色
- [ ] 釘の「材料として使う」に「[建築]」のレシピが出る
- [ ] 検索欄の列に「作成可」のチェックボックスがある。チェックを入れると、今の持ち物と周りの容器で作れるアイテム・建てられる建築物だけになる。選択肢と組み合わせられる（「建築」＋「作成可」で今建てられる建築物だけ、「作成不可」＋「作成可」で何も出ない）。材料を拾う・捨てる・容器から出すと、少しして一覧が変わる。作業面（机など）のそばに行く・離れると変わる
- [ ] 「作成可」にチェックを入れると、作れるものが上に、作れないものが下に暗く並ぶ。オプションの「作成可のとき、作れないものも暗く表示する」を OFF にすると、作れないものは出なくなる（ウィンドウを開いたままでも変わる）
- [ ] 「作成可」にチェックを入れると、右側の「作り方」「材料として使う」「道具として使う」で、今作れないレシピが暗くなる（開いた中の行も）。作れるレシピは明るいまま。オプションで隠すにしていても、右側は暗くなるだけで消えない。チェックを外すと元に戻る
- [ ] 「作成可」にチェックを入れたまま歩き回っても、目立つ引っかかりがない
- [ ] 「壁」「wall」などで検索すると建築物が見つかり、絞り込みの「建築」で建築物だけになる。選ぶと、その建築のレシピの材料・道具・条件が出る。右クリック →「建築する」で建築の画面が開く
- [ ] 表記がゲームと同じ（「[製作]」「[建築]」「材料」「完成品」）
- [ ] 左の一覧・右のアイテムの行を右クリックすると、製作で作れるアイテムなら「製作する」が出て、押すと製作の画面がそのアイテムのレシピに絞り込まれて開く。作れないアイテムには出ない
- [ ] 右の「[製作]」のレシピの行を右クリック →「製作する」で、製作の画面がそのレシピを選んだ状態で開く
- [ ] 右の「[建築]」のレシピの行を右クリック →「建築する」で、建築の画面がそのレシピを選んだ状態で開く
- [ ] 右クリックのメニューにウィッシュリストの行が出て、追加・削除ができる（F06 が ON のとき）。レシピの行では、その完成品について出る
- [ ] レシピで作れないアイテム（絞り込みの「作成不可」で出るもの）では「レシピでは作れません」と出る
- [ ] ウィンドウの大きさを変えると、一覧と右の表示が合わせて伸び縮みする。閉じて開き直しても位置と大きさが残る
- [ ] 「有効にする」を外すと、ボタンが消え、キーでも開かない
- [ ] MOD のレシピも出る（ほかの MOD を入れたとき。入れていなければ省略）
- [ ] マルチプレイ（ローカルで立てたサーバー）でも同じように動く

段階 2：

- [ ] 開いたレシピの中で、製作で作れる材料の行に「[+]」が付き、押すとその下に字下げしてその材料の作り方が出る。出た材料もさらに開ける。作れない材料には「[+]」が付かない
- [ ] 「材料として使う」「道具として使う」のレシピの中でも、同じように開ける
- [ ] 道具の行は初めは開けない。右側の上の「道具も展開」にチェックを入れると開ける。閉じて開き直してもチェックが残る
- [ ] 「ハンマー など5種」の行を開くと、数が足りている候補、持っているが足りない候補、持っていない候補の順に並ぶ。行の名前も先頭の候補になる。それぞれの候補も開ける
- [ ] 作り方が複数あるアイテムでは、今作れるレシピが先に並ぶ（「作成可」のチェックがなくても）
- [ ] 材料を拾う・捨てると、少しして右側の並びが変わる
- [ ] 循環する材料（開いた先に上と同じアイテムが出る）は、そこから先が開けない
- [ ] 「戻る」「進む」で戻ったときも、開いた形が残る
- [ ] 「作成可」にチェックが入っているときは、開いた中の今作れないレシピも暗くなる

段階 3：

- [ ] 絞り込みに「料理」「修理」がある。「料理」でスープなどの完成品が、「修理」で直し方があるアイテムが出る
- [ ] 料理の完成品（スープなど）を選ぶと、作り方に「[料理]」の行が出る。同じ名前の料理（鍋とバケツ）は1行。開くと器・材料・完成品・材料の上限・加熱できるかが出る
- [ ] 鍋を選ぶと「料理のベースとして使う」、にんじんなどを選ぶと「料理の材料として使う」が出る
- [ ] 直し方があるアイテム（武器など）を選ぶと「直し方」が出る。開くと直せるもの・修理材（数とスキル）・共通で要るもの・倍率が出る。修理材のアイテムでは「修理に使う」が出る
- [ ] 「作成可」で、鍋と材料を持つと料理が、直すものと修理材を持つと修理が明るくなる
- [ ] オプション「隠しレシピを表示する」を ON にすると、隠しの料理も出る（ウィンドウを開いたままでも変わる）
- [ ] 「[料理]」「[修理]」の行の右クリックで、ウィッシュリストの行が出る
