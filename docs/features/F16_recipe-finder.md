# F16 レシピ検索

- 状況：⬜ 未実装
- 一覧に戻る：[features.md](../features.md)

## 要望

- 内容：アイテム名で検索して、そのアイテムの作り方（制作・建築・料理・修理）と使い道（何の原料・道具になるか）を、ゲームの中のウィンドウで調べられるようにする。原料の作り方も順にたどれるようにする
- 困っている場面・理由：本体の制作の画面は「今作れるか」を見る画面で、「このアイテムは何に使えるか」「原料をどこから作るか」をまとめて調べにくい。ゲームの外の HTML のツールでは調べられるが、ゲームを離れる必要があり、バニラ（MOD なし）の決まった版のデータしか載らない
- 元になるもの：itsu07 さんの HTML のアプリ「PZ レシピ検索」（`pz_recipe_finder.html`、42.21.0 用）。画面の作りと表示する内容を参考にし、コードは Lua で作り直す
- 優先度：

## 調査結果

- 既存MOD：Context Menu Crafting [B42]（3425516353）は、アイテムの右クリックで、それを材料に使うレシピを出す（F12 の調査を参照）。作り方・使い道・原料の展開をまとめて調べる画面は見つかっていない
- B42.21のMPで動くか：―
- クライアントだけで実現できるか：できる。レシピはどれもクライアントにあるスクリプトのデータから読める。サーバーとのやり取りも、セーブデータへの書き込みも要らない
- データの量（B42.21 のゲーム本体のスクリプトを数えた）：
  - 制作のレシピ（`craftRecipe`）約970、建築の項目（`entity`）約460、料理（`evolvedrecipe`）約440、修理（`fixing`）29
  - アイテムは約1万種類あるが、検索の対象はレシピに出てくるものだけ（数千）なので、最初に一度で索引を作っても引っかかりはほぼ出ない見込み（ゲームの中で測って確かめる）
- データの読み方（ゲームの Lua で使われているもの。B42.21 で確かめた）：
  - 制作と建築：`ScriptManager.instance:getAllCraftRecipes()`。建築の画面の項目も `CraftRecipe` を持つ（`ISEntityBuildMenu.lua` の `info:getRecipe():getCraftRecipe()`）。建築かどうかは `isBuildableRecipe()`、建築の分類は `getBuildCategory()`
  - 材料と完成品：共通の `SurvivorComforts.forEachRecipeItem`（`Recipes.lua`）で読める。原料1つごとに：
    - 消費しない（道具）か：`isKeep()`、`isTool()`
    - 数：`getIntAmount()`。数が決まっていないもの：`isVariableAmount()`
    - なれるアイテム：`getPossibleInputItems()`（「ハンマーならどれでも」のようなタグの指定も、アイテムの一覧に直して返す）
    - 液体・エネルギー：`getResourceType()` で分かる。液体は `getPossibleInputFluids()`
  - 必要なスキル・習得・明るさ・場所：`getRequiredSkillCount()` と `getRequiredSkill()`、`needToBeLearn()`、`canBeDoneInDark()`、`isAnySurfaceCraft()`、`isCanBeDoneFromFloor()`（本体の制作の画面 `ISWidgetTitleHeader.lua` などが使うもの）
  - 料理（スープ・サラダなど）：`getEvolvedRecipes()`（`ISInventoryPaneContextMenu.lua`）
  - 修理：`FixingManager.getFixes(item)`（`ISInventoryPaneContextMenu.lua`）。アイテムの実物を渡す形なので、全部の修理の一覧を読む方法は実装のときに調べる
- HTML 版との違い：
  - ゲームが読み込んだレシピをそのまま使うので、サーバーで入れている MOD のレシピも出る。ゲームを更新しても古くならない
  - 一覧のデータ（HTML 版は 3.4MB）を MOD に入れる必要がない。最初に開いたときに一度だけ索引を作る
- 使い回せるもの：
  - 共通の検索（`Search.lua`：ひらがなとカタカナを区別しない、空白で絞り込む）と、F14 の英語名の表
  - ウィンドウの共通部品（`Window.lua`）と画面左のボタン。一覧は F06・F09 と同じ `ISScrollingListBox` を元にする
  - F12 の「作れるアイテムの一覧」と、制作の画面を開いて絞り込む処理（`Recipes.lua`）
- 難しさ：中〜高。新しいウィンドウ（検索欄・結果の一覧・詳しい表示・原料の展開）が要る。料理と修理は、データの読み方を調べるところから
- 判定：**自作**（itsu07 さんの HTML のアプリを元に、Lua で作り直して Survivor Comforts に入れる）

## 仕様

### 段階

段階を分けて作る。まず 1 を作り、2 以降は 1 を使ってみてから細かいところを決める。

1. 制作と建築の作り方と使い道
   - 建築も制作と同じレシピの一覧に入っているので、最初から「建築」と書いて一緒に出す
2. 原料の展開と、どの本で覚えるか
   - 本で覚えるレシピは、本のアイテムを全部調べる必要があるので、ここで作る
3. 料理と修理
   - 読み方が制作と違うので、最後に作る

### ファイル

- `client/SurvivorComforts/RecipeIndex.lua`：索引を作る（画面とは分ける。テスト用の MOD で確かめやすくするため）
  - アイテム（`fullType`）→ 作るレシピ、原料として消費するレシピ、道具として使うレシピ
  - 検索の対象のアイテムの一覧（どれかのレシピに出てくるもの）
  - F12 の「作れるアイテムの一覧」（`Recipes.lua` の `hasRecipe`）は、あとでこの索引に寄せて1つにする
- `client/SurvivorComforts/F16_RecipeFinder.lua`：ウィンドウと表示
- 翻訳（日本語・英語）に `F16_*` を足す

### 索引

- 最初にウィンドウを開いたときに一度だけ作る。レシピは遊んでいる間に変わらないので、作り直さない
- 目立つ引っかかりが出るなら、何回かに分けて作る
- 作れなかったとき（エラー）は、ログに出し、ウィンドウには「レシピを読めませんでした」と出す

### 画面

- 外枠は `Window.lua` で作る（F08・F09 と同じ。大きさを変えられ、位置と大きさを覚える）
- 開き方：画面左のボタンと、オプションで決めたキー（初期値はキーなし）
  - F12 の右クリック「レシピを見る」と、F06 のウィッシュリストから開けるようにするかは、段階 1 を使ってみてから決める
- 並び（HTML 版と同じ）：
  - 上：検索欄と、絞り込みの選択欄（すべて／作れる／素材（作れない））
  - 左：検索結果のアイテムの一覧（アイコンと名前）
  - 右：選んだアイテムの情報
- 右の情報は、文章の欄ではなく、1行ずつの一覧（`ISScrollingListBox` を元にする）で作る
  - 行の種類：見出し（作り方・使い道）、レシピ（名前と「制作」「建築」の区別）、原料・道具、条件（スキル・習得・明るさ・場所）
  - アイテムの行をクリックすると、そのアイテムの情報に移る。「戻る」で前に戻れる
  - 段階 2 の「原料を展開」は、原料の下に字下げした行を足して作る
- 作り方：レシピごとに
  - 原料（消費）と道具（消費しない）を分けて、数と一緒に出す
  - 「ハンマーならどれでも」のように、なれるアイテムが複数ある原料は「ハンマー など5種」と1行にまとめ、クリックで全部を開く
  - 液体の原料は、名前と量の文字だけで出す
  - 必要なスキル、習得が要るか、明るさが要るか、作る場所
- 使い道（逆引き）：原料として消費するレシピと、道具として使うレシピを分けて出す
- この画面から作る操作はしない（調べるだけ）。作るときは本体の制作・建築の画面を使う。本体の画面へのボタン（F12 と同じ絞り込み）を置くかは、段階 1 を使ってみてから決める
- 出さないもの：HTML 版の「定義の原文」（ゲームの中ではスクリプトの原文が読めないため）と、ダーク表示の切り替え（ゲームの UI の色に合わせる）

### 検索

- 共通の検索（`Search.lua`）を使う。ひらがなとカタカナを区別せず、空白で区切ると全部を含むものに絞り込む
- F14 を有効にしていれば、英語名でも見つかる
- 対象は、どれかのレシピの原料・道具・完成品になっているアイテム

### オプション・そのほか

- オプション：`F16_enabled`（有効にする）、`F16_key`（開くキー）。見出しは「レシピ」（F12・F03・F07 と同じ）
- セーブデータには何も書き込まない。サーバーの処理はない
- 元のアプリの作者（itsu07 さん）を README・機能の一覧・ワークショップの説明に書く。元のコードは使わないが、ライセンス（F02・F15 と同じく MIT か）と表示の仕方を作者に確かめてから公開する

### テスト

- 索引は、テスト用の MOD（[testing.md](../testing.md)）に足す。例：板（`Base.Plank`）で調べると、作り方と、原料として使うレシピが出る。釘で調べると、使い道に建築が出る
- 画面は、ゲームの中で見て確かめる（確認項目）
