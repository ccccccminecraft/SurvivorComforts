## 1. 不具合

### 問題がなかったこと

- **エラーの守り**：
  - 本体の関数への割り込み、イベント、ボタン・メニューの処理は、どれも `SurvivorComforts.safeCall`（`pcall`）を通る
  - サーバーは、受け口（`ServerCommands.lua`）で `pcall` する
  - 設定画面の読み込み（`PZAPI.ModOptions.load`）への割り込みも `pcall` で囲んである（R5-1 のとおり）
- **F16 の右側の行の高さ**：いちばん上のアイテムの行だけ高い。本体の一覧（`ISScrollingListBox`）は、行ごとの高さ（`item.height`）でクリックの位置（`rowAt`）と描く位置を決めるので、ずれない
- **F16 のレシピの中身を書き換えない**：中身（`recipeIndex.describe`）は覚えて使い回す。並べ替え（`sortItems`・`sortRecipes`・`sortByKey`）はどれも新しい表を返すので、覚えた中身は変わらない
- **F16 の材料の展開の止め**：今見ているアイテム、上の段にあるアイテム（循環）、深さ 20 段で止まる（`client/SurvivorComforts/F16_RecipeFinder.lua:273-277`）
- **F16 の戻る・進む**：ブラウザと同じ動き（50 件まで）。左の一覧は、作れるものの組が変わったときだけ作り直す
- **F16 の判定の仕組み**：プレイヤーのオブジェクトが変わる（死んで作り直す）と作り直す（`client/SurvivorComforts/RecipeCanMake.lua:138-142`）
- **F16 の索引が作れなかったとき**：ログに1回出し、ウィンドウには「レシピを読めませんでした」と出す。F03・F06・F12 の「レシピを見る」は、いつも出す
- **`Search.lua` の名前の文字の覚え方**：名前が変わったとき（名前を付けた袋、言語の変更）は、名前を比べて作り直す
- **F06**：
  - 自分のリストの読み書きは、空の行と重なりを除く
  - 届いた「みんなのリスト」は、形を確かめてから使う（文字列でない名前は捨てる）
  - 上限（100・30・300）は画面でもサーバーでも確かめる
- **F07**：本体のメニュー作りの間だけ関数を差し替え、エラーが出ても必ず元に戻す（`client/SurvivorComforts/F07_CookingStack.lua:139-144`）
- **F08**：プレイヤーが死ぬとウィンドウを壊し、作り直す。本体の `ISCharacterInfo.instance` を上書きしない
- **F09・F15**：答えの形を確かめてから使う。F15 は、答えのユーザー名が今見ている人と違えば捨てる
- **ウィンドウの位置**：`ISLayoutManager.RegisterWindow` は同じ名前を上書きするので、F08 がウィンドウを作り直しても、登録が重ならない

## 2. ゲームの Lua（Kahlua）の落とし穴

### 問題がなかったこと

- 「機械的に確かめて問題がなかったこと」のとおり、使っていない関数、ソースの日本語、検索まわりのパターンの問題はない
- **検索（`Search.lua`）**：日本語を含む文字は1文字ずつ（`string.sub`）読み、比べるのは `plain` の `find` だけ
- **F14**：本体の検索の文字の切り分けも `plain` の `find`（`client/SurvivorComforts/F14_EnglishSearch.lua:51`）
- **Java のオブジェクトを表の鍵にしている所**（`keys[recipe]`・`described[recipe]`、F02 の `dimmed[row]` など）：同じものは同じオブジェクトなので、引ける
- **F16 の名前の並べ替え**：同じ名前のときに内部名で比べるので、順番がぶれない
- **F15 の並べ替え**：本体のスキルの画面と同じ `string.sort` を使っている
